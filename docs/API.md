# MissionGuard AI — API Reference

Base path: `/api` (all routes below are prefixed with this unless noted). Interactive OpenAPI docs are available at `/docs` when the backend is running. A single unprefixed `GET /health` also exists as a deployment-probe alias of `GET /api/health`.

All request/response bodies are JSON. Field types below reflect the actual Pydantic models in `backend/app/schemas/models.py`.

---

## Health

### `GET /api/health`

Returns backend status and which AI explanation provider is active.

**Response**

```json
{
  "status": "ok",
  "explanation_provider": "template-offline (Granite-interface compatible)"
}
```

---

## Spacecraft

### `GET /api/spacecraft`

Returns the fleet roster. For each spacecraft, if telemetry exists for its mission, status/health are recomputed live from current risk (`HEALTHY`/`WARNING`/`CRITICAL`); otherwise the stored `STANDBY` default is returned. The roster is seeded at startup with three demo spacecraft: `SC-001`/`MISSION-001`, `SC-002`/`MISSION-002`, `SC-003`/`MISSION-003`.

**Response**: array of `Spacecraft` objects (`spacecraft_id`, `mission_id`, `name`, `status`, `health`).

## Telemetry

### `POST /api/telemetry/simulate`

Generates a deterministic, seeded telemetry run and runs the full detect → risk pipeline against it, storing the results.

**Query parameter**: `detector` (default `isolation_forest`) — one of `isolation_forest`, `one_class_svm`, `autoencoder`.

**Request body** (`ScenarioRequest`):

```json
{
  "mission_id": "MISSION-001",
  "spacecraft_id": "SC-001",
  "scenario": "battery_degradation",
  "duration_minutes": 90,
  "severity": 75,
  "interval_seconds": 30,
  "seed": 42
}
```

`scenario` must be one of: `normal`, `battery_degradation`, `thermal_anomaly`, `communication_anomaly`, `sensor_anomaly`, `compound_anomaly`.

**Response**

```json
{
  "mission_id": "MISSION-001",
  "detector": "isolation_forest",
  "points_generated": 180,
  "anomalies_detected": 1,
  "mission_health": 62.4,
  "risk": { "risk_level": "MEDIUM", "risk_score": 42.1, "factors": [...], "subsystem_breakdown": {...} }
}
```

### `GET /api/telemetry/{mission_id}`

Returns raw simulated telemetry points for the mission (most recent scenario run).

**Query parameter**: `limit` (default 500) — returns the last N points.

### `GET /api/missions/{mission_id}/status`

Returns a current health/risk snapshot derived from whatever telemetry/anomalies already exist, independent of which client generated them — used by pages to rehydrate state on load. If no telemetry exists, returns `mission_health: 100.0`, `risk: null`.

## Anomalies & Predictions

### `GET /api/anomalies?mission_id=...`

Returns the list of `Anomaly` records for the mission.

### `GET /api/anomalies/{mission_id}/{anomaly_id}`

Returns the full anomaly detail: the `Anomaly`, its `Forecast`, the current `RiskAssessment`, and an `ExplanationResponse` generated by the active AI provider. **Returns HTTP 404** if the anomaly does not exist.

### `POST /api/anomalies/{mission_id}/{anomaly_id}/status`

Sets an anomaly's operator-controlled status.

**Query parameter**: `status` — one of `NEW`, `INVESTIGATING`, `ACKNOWLEDGED`, `MONITORING`, `RESOLVED`. Returns 404 if the anomaly does not exist.

### `GET /api/predictions/{mission_id}?parameter=battery_voltage`

Returns a `Forecast` for the given telemetry parameter. **Returns HTTP 404** if the mission has no telemetry.

### `POST /api/ai/explain?mission_id=...&anomaly_id=...`

Returns only the `ExplanationResponse` portion of the anomaly detail (same underlying computation as the detail endpoint).

### `GET /api/recommendations?mission_id=...`

Returns the list of `RecommendationCard` objects generated for the mission's anomalies so far.

## Mission Copilot

### `POST /api/copilot/chat`

**Request** (`CopilotRequest`):

```json
{
  "mission_id": "MISSION-001",
  "question": "Why is the power subsystem showing abnormal behavior?",
  "context_anomaly_id": null
}
```

The route applies a small intent router before falling back to general evidence-grounded Q&A: questions containing "conjunction"/"debris"/"collision" are answered from stored conjunction data; questions containing "maneuver"/"mission plan"/"feasib"/"can we perform" are answered from the most recent Mission Planner evaluation. Otherwise the question is answered against the evidence for `context_anomaly_id` (if given) or the mission's most severe active anomaly.

**Response**

```json
{ "answer": "...", "context_anomaly_id": "abc12345" }
```

### `GET /api/copilot/history?mission_id=...`

Returns the stored `CopilotMessage` history (user + assistant turns) for the mission.

## Mission Planner

### `POST /api/mission-planner/evaluate`

**Request** (`MissionPlanRequest`):

```json
{
  "mission_id": "MISSION-001",
  "spacecraft_id": "SC-001",
  "objective": "Earth Observation Pass",
  "start_in_minutes": 10,
  "duration_minutes": 18,
  "required_power_w": 145,
  "requires_communication": true,
  "requires_attitude_maneuver": true,
  "min_fuel_pct": 5.0,
  "max_temperature_c": 50.0
}
```

**Returns HTTP 404** if the mission has no telemetry yet.

**Response**

```json
{
  "evaluation": {
    "objective": "Earth Observation Pass",
    "checks": [
      { "constraint": "Power", "status": "UNSAFE", "detail": "..." },
      "..."
    ],
    "overall": "UNSAFE",
    "recommendation": "...",
    "confidence": 0.9,
    "evidence": ["..."]
  },
  "narrative": "AI-generated explanation of the evaluation"
}
```

### `GET /api/mission-planner/{mission_id}`

Returns the mission's stored history of `MissionPlanEvaluation` results.

## Space Situational Awareness

### `GET /api/space-objects/summary`

Returns a simulated catalog-size figure for display purposes.

```json
{ "tracked_objects": 12345, "data_source": "SIMULATED" }
```

### `POST /api/conjunctions/screen?mission_id=...&spacecraft_id=...&seed=7`

Generates a fresh set of simulated `ConjunctionEvent` objects and stores them, replacing any prior screening for the mission.

### `GET /api/conjunctions?mission_id=...`

Returns the mission's currently stored conjunction events.

### `GET /api/conjunctions/{mission_id}/{conjunction_id}/explain`

Returns an AI-generated explanation of one conjunction event (always prefixed `[SIMULATED DATA]`). Returns `{"error": "not found"}` (not an HTTP error status) if the event id doesn't exist — a known, harmless inconsistency versus the rest of the API's 404 convention.

---

## Model Evaluation

### `GET /api/models/evaluate?scenario=battery_degradation&severity=70&duration_minutes=90`

Generates a fresh, separately-seeded telemetry run and computes real precision/recall/F1/false-positive-rate/detection-latency for all three registered detectors against it.

**Response** (`EvaluationReport`): `scenario`, `generated_at`, `results` (array of `DetectorMetrics`), `note`.

### `GET /api/models/evaluate-forecast?scenario=battery_degradation&parameter=battery_voltage&severity=70&duration_minutes=90`

Fits the forecast on the first 80% of a fresh run and computes MAE/RMSE against the held-out remaining 20%.

---

## Reports

### `POST /api/reports/generate?mission_id=...`

**Returns HTTP 404** if the mission has no telemetry. Otherwise computes a fresh risk/forecast, generates an AI explanation per active anomaly, an AI executive summary, and returns a `MissionReport` (see `ARCHITECTURE.md` §9 for contents). The report is stored and also returned in the response.

### `GET /api/reports/{mission_id}`

Returns the mission's stored report history.

---

## Error Behavior

- Endpoints that require existing telemetry (`predictions`, `mission-planner/evaluate`, `reports/generate`) return **HTTP 404** with a descriptive `detail` message when none exists.
- `GET /api/anomalies/{mission_id}/{anomaly_id}` and `POST .../status` return **HTTP 404** for an unknown anomaly id.
- All other endpoints return default FastAPI/Pydantic validation errors (HTTP 422) for malformed request bodies.
- The Granite/AI provider layer never raises an unhandled error to the API layer — on failure it falls back to the deterministic template provider and labels the response accordingly (see `GRANITE_INTEGRATION.md`).
